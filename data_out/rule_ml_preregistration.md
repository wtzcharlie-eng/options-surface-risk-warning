# 问题1 规则+ML 融合 · anchor 连续口径达标研究 —— 预登记判据

> **本文件在读测试集之前写定。** 判据一经写下不得修改；结果跑完后追加在文末。

---

## 前情：为什么走到这一步

§7.21 已证伪**过滤类杠杆**：冷却去抖 −2.8~−3.7pp、流动性门 +0.32pp，
36 个配置在验证集上无一可行。纯规则的 P-R 前沿**不包含目标角点**。

剩下的只有**加信息**这一类。赛题问题1 原本就要求「规则 + ML 融合」，
但**当前所有 anchor 连续口径的评测都跑的是 `model=None`（纯规则）**。

**既有的 ML 模型不能用**，两个原因：
1. **泄漏**：`train_anchor_predictor.py` 的训练区间是「2023–2025 四品种」，
   而 anchor 测试集是 2025-07~2026-04 —— **训练数据覆盖测试期**；
2. **融合方向错**：`alert_engine.evaluate` 的融合是 `level = max(rule_level, ml_level)`，
   **只能加预警、不能减**，而我们缺的是精确率。

故本研究：**重训**（只用 anchor 训练集）+ **改融合方向**（否决式，而非 max）。

## 已做的探索性预测（必须如实声明）

跑本研究之前，已在**验证集**上做过一次可行性预测（测试集未读）：
基线 P@R60 = 42.76%；加 ML 否决后在 R=64.13% 处达到 **54.99%**、lead=50.9min。
**即本研究的设计（否决式融合、阈值网格范围）是在看过验证集网格之后定的。**
这属于「探索 → 确证」的正常流程，但必须写明：
**验证集上的那个 54.99% 不是独立结果，测试集才是。**

---

## 模型与融合规则（跑数前写定）

- 模型：`HistGradientBoostingClassifier(max_iter=200, learning_rate=0.08,
  max_leaf_nodes=31, random_state=0)`
- 特征：与 DRL 相同的 32 维（26 曲面 + 6 标的），**不新增特征**
- 标签：`anchor` 的 `y`（未来 8 个截面内有风险起点）
- **训练集：仅 anchor 训练集（2023-01 ~ 2024-12，7 品种）。验证集与测试集一律不参与训练。**
- 融合：**否决式** —— `if ml_prob < thr: level = 0`，否则保留规则等级。
  **不使用 `max()`**：那只会增加预警、降低精确率，与目标相反。

## 泄漏门（必须通过，否则本研究作废）

> **打乱训练标签后重训，验证集 AUC 须塌陷到 0.5±0.05。**

若不塌陷，说明特征里有位置性泄漏，整个结论不成立。

## 选择协议

1. **只在验证集上选**。测试集在整个选择过程中一次都不读。
2. 网格：`zmult ∈ {0.40, 0.55, 0.70, 0.85}` × `thr ∈ {0, 0.15, 0.25, 0.35, 0.45}`
3. 在验证集上同时满足 `P≥50% 且 R≥60% 且 lead≥30min` 的候选中，取**精确率最大**者。
4. 若验证集无可行点 → 不评测试集，结论即「不可行」。

## 达标判据

> 所选配置在**测试集**上同时满足 **精确率 ≥50% 且 召回 ≥60% 且 平均提前 ≥30min**。

## 必须并列披露（缺一不可）

1. **泄漏门结果**（打乱标签后的 AUC）
2. **纯规则基线**在同一测试集、同一死区过滤下的成绩 —— 用于量化 ML 带来的增量
3. **同召回处的精确率对比**（证明是移动前沿而非沿前沿滑动）
4. **DRL 在同一口径的成绩** —— 防止只报问题1、让人误以为它追平了问题3
5. 预警数变化
6. **「这已不是纯固定阈值系统」这句话必须出现在所有引用处**

## 预设的失败情形（写在前面）

- **若泄漏门不过**：本研究作废，不报任何数字。
- **若验证集无可行点**：结论即「ML 否决也推不动前沿」，不评测试集。
- **若测试集不达标**：如实报出，计入本项目已有的「验证集→测试集选择误差」记录，
  **不重选工作点、不换模型、不调网格**。
- **若达标**：必须同时写明以下三点，缺一不可：
  1. **§7.21 的结论需改写**：从「规则引擎在连续口径上够不到」改为
     **「纯规则够不到，规则+ML 融合可以」**——原结论对**纯规则**仍然成立，不得删除；
  2. **问题1 与问题3 的界限被压缩了**：两者现在都用同一批 32 维特征的监督/强化模型。
     赛题允许问题1 用规则+ML，但**必须声明这一点**，不得让读者以为
     「固定阈值也能达标」；
  3. 这**不改变**「固定阈值僵化、需要自适应」的结论——恰恰相反，
     它再次说明**光靠阈值不够，必须加学习成分**。

## 结果

> 2026-08-26 跑出，**判据未作任何修改**。复算：`python scripts/rule_ml.py --underlying`

### 泄漏门：**通过**

验证集 AUC **0.7580**；打乱训练标签后重训 AUC **0.4838**
（判据 0.5±0.05）→ 特征里没有位置性泄漏，结论成立。

### 达标判据：**通过**

验证集选中 `zmult=0.4` / `thr=0.35`，测试集只评一次：

| | 精确率 | 召回 | 平均提前 | 预警数 | 三项全达标 |
|---|---|---|---|---|---|
| **规则+ML 融合** | **53.86%** ✓ | **62.25%** ✓ | **48.1min** ✓ | 6,493 | **✓** |
| 同 zmult 纯规则 | 39.27% ✗ | 82.12% ✓ | 49.1min ✓ | 12,339 | ✗ |
| 纯规则 R≈60% 处 | 49.05% ✗ | 60.50% ✓ | 49.2min ✓ | 6,100 | ✗ |

**同召回量级上 +4.81pp** —— 这是**移动前沿**，不是沿前沿滑动。

### 验证集→测试集传导良好

验证集 P=54.99% → 测试集 P=53.86%，落差仅 **-1.14pp**，
方向一致、量级接近。这与 §7.20 CVaR 那次「验证集全负、测试集才转正」形成对比——
那次的正结果不是选点方法带来的，**这次是**。

### 三条必须一起写的限定

**① §7.21「纯规则够不到」的结论仍然成立，未被推翻。**
本节的结论只适用于**融合后**的系统。纯规则的 P-R 前沿依旧不含目标角点
（同 zmult 纯规则 39.27%、R≈60% 处 49.05%，都够不到 50%）。

**② 这已不是纯固定阈值系统。**
它用了一个在 anchor 训练集上训练的监督模型（32 维特征，与问题3 DRL 同一批），
以否决式融合压掉低概率预警。赛题允许问题1 用「规则+ML 融合」，
但**引用 53.86% 时必须说明这一点**，不得让读者以为「固定阈值也能达标」。

**③ 这不改变「固定阈值僵化、需要学习成分」的结论——恰恰再次印证了它。**
过滤类杠杆（冷却、流动性门）全部无效，只有**加入学习成分**才推动了前沿。

### 补充：融合系统在**两个口径**下都达标

概览卡引用的是**新口径**（事件级精确率、召回不设上限），而本研究选点用的是**旧口径**
（截面级、120min 窗）。**只报一个会让读者以为另一个也这样**，故两个都给
（同一配置 `zmult=0.4` /
`thr=0.35`，**未重选**）：

| | 旧口径（截面级/120min 窗） | 新口径（事件级/不设上限） |
|---|---|---|
| **规则+ML 融合** | 53.86% ✓ / 62.25% ✓ / 48.1min ✓ | **54.49% ✓ / 95.02% ✓ / 1322min ✓** |
| 同 zmult 纯规则 | 39.27% ✗ | 41.82% ✗ |

**两个口径下纯规则都不达标，融合后都达标。**

> 概览卡里那个 **45.0%** 是**纯规则在另一个工作点**（`zmult=2.0`）的新口径数，
> 与本表的 41.82%（`zmult=0.4`）是不同配置，不要混为一谈。
> 卡片已改为同时显示纯规则与融合两行。

### 交付件：模型已落盘，融合已接进引擎

本研究初版**只是一个评测脚本**——每次运行重训、不落盘，于是「有一个达标的结果」
却「没有一个可部署的系统」：`scan.py` 与仪表板都调用不到，融合规则也只存在于脚本里。
现已补齐三件：

1. **模型落盘** `data_out/rule_ml_model.joblib`（32 维特征、
   87,517 行训练样本、正样本率 29.6%），
   附指纹 `rule_ml_model.fingerprint.json`（特征名与顺序、切分边界、模型参数、sklearn 版本）。
   **特征顺序尤其要守**：模型按列序吃数，顺序变了不会报错，只会静默给出错误概率。
2. **融合接进交付本体** `vol_surface.alert_engine.evaluate(..., veto_prob=, veto_thr=)`。
   **不改默认行为**：`veto_prob=None` 时与改动前逐位一致，问题1 既有结果不受影响。
3. **两道门**：
   - `G13`（`drl/tests.py`）：对 **600 例金标准夹具**逐位比对，确保公共路径未被改动；
     并验证「只给一半参数不得生效」「启用时须与 `rule_ml.fuse` 语义一致」。
   - `check_doc_numbers.py`：报告里有达标配置时，**模型文件必须存在且指纹匹配**。

> G13 的 (a) 项初版是拿「带/不带 veto 参数」互比——**那是自指的**：
> 两者走同一段代码，被污染时会一起变、仍然相等。实测注入
> `if level >= 3: level = 2` 后该门照样通过。故改为对照**改动前生成的金标准夹具**。
> 三种注入（污染公共路径 / 语义不一致 / 只给一半参数即生效）现已全部能抓到。

### 与同口径 DRL 的对照

> 提醒：下表的融合成绩来自**规则+ML**，**不是纯规则**——
> 纯规则在同一测试集上 R≈60% 处只有 49.05%，整条前沿够不到目标角点（见 §7.21）。


| | 精确率 | 召回 | 平均提前 |
|---|---|---|---|
| 规则+ML 融合 | 53.86% | 62.25% | 48.1min |
| DRL（lean=0.3） | 54.15% | 74.93% | 36.2min |

精确率基本持平（DRL 高 +0.29pp），
但**DRL 的召回高出 +12.68pp**——
在同样达标的前提下覆盖了明显更多的风险起点。
